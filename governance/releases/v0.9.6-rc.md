# LOC 0.9.6-RC — GameBoard、Supabase First 與 Admin 備援切換

**套件版本：** `0.9.6-rc`  
**iOS 原生版本：** `0.9.6 (8)`  
**日期：** 2026-10-14  
**性質：** Release Candidate；iOS arm64 未簽署 IPA  

## 本次驗收範圍

- GameBoard 已恢復真正的預設匯出，LunaRunes 桌遊介面及資料契約由 Playwright 驗收。
- Supabase 維持主要資料庫：公開讀取與一般認證資料操作透過 Data API／PostgREST，避免為每一筆瀏覽器請求建立獨立 PostgreSQL 連線。
- Neon 保留 LOC 專屬緊急備援；Admin 的「儲存設定」與「切換至此資料庫」分開，只有管理員明確要求才切換。Neon 備援目前只提供公開讀取，不能視為具有完整寫入容錯能力。
- Admin 連線設定採 Type／Provider／Link；Region／Area 可供各服務商記錄地區，Supabase Pooler 新連線須提供有效 Region。標準 SQL 使用 Host:Port／Database／User／Password。
- SQLite 的遠端資料庫選擇在沒有可信任 Gateway 前不可啟用，既有本機 SQLite 支援不受影響。
- 修正高併發瀏覽器驗收下關鍵詞頁面的載入等待時間，仍須出現標題且不允許跳過斷言。

## 封裝與發布門檻

- GitHub `main` 提交後，由 RC 專屬流程依序執行 repository contracts、Supabase 公開 Data API、Next 靜態建置和 Desktop／Mobile Playwright。
- 全部成功後才進行 Xcode iPhone 實機 arm64 Release 編譯、Capacitor 8、原有 AppIcon 及 66 張純數字 ASCII 符文卡驗證。
- Bundle ID：`cc.lo3rwang.loc.mobile`；MARKETING_VERSION `0.9.6`，CURRENT_PROJECT_VERSION `8`。
- GitHub prerelease：`v0.9.6-rc`；預期資產：`LOC-0.9.6-RC-unsigned.ipa`。

## 限制

IPA 未簽署，須自行進行合法 Apple 裝置簽署後才能安裝。CI 通過不等於真機登入、Admin 變更資料庫的完整容錯切換，或外部 MySQL／SQL Server 的實際連線測試通過。

此文件觸發 RC 封裝流程，但**僅在 GitHub Release 實際發布且 IPA 資產存在後，才算封裝完成**。
