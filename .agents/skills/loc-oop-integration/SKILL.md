# LOC OOP／模組深度整合

本 Skill 與儲存庫根目錄 `AGENTS.md` 一起執行；它是具體操作程序，不取代既有作品、治理、抽牌和資料庫權限限制。

## 執行程序

1. **鎖定責任與基線**：確認使用者授權範圍、目前 `main` 程式碼、套件版本和實際操作流程。絕對不把現有功能、特殊頁或舊功能預設成可刪除。使用者已禁止修改資料庫時，整個工作流程不得執行資料庫變更。
2. **全專案盤點而非單頁修補**：搜尋元件、Hooks、`.mjs`／`.js`、import、動態載入、路由、測試、手機版和 Admin，列出「能力 → 共用核心 → 基本／延伸配置 → 所有呼叫端 → 驗證」。將沒有直接 import 的舊功能列為待確認／可恢復，不能直接刪。
3. **現成模組優先且深度採用**：核對實際安裝版本與官方文件，優先使用套件的完整元件、插件、擴充與錯誤處理流程。只允許最薄的必要資料欄位 Adapter；不得重新實作套件本身已有的 Editor、列表、搜尋、圖表、分頁或序列化。
4. **以 OOP 思維落地**：按單一責任與共用介面設計一個核心，變化由設定和 Extension 決定。React 使用組合與 Hooks 實現此原則，不強迫 `class`；同一功能不能在不同頁面維護互不一致的副本。整理 `.mjs` 時，應收斂多餘膠水、重複流程與平行實作，不要僅重新命名。
5. **相容性不可破壞**：首頁的固定與延伸區塊、Scope／Article／Attr 的操作手感、BlockNote 所見即所得、圖表基本及延伸模式、Rune 的 2D／3D 與特殊頁、OW3gs 適用的所有抽牌法則，都保留原有行為及核心資料。不得藉整合改動資料庫或抽牌演算法。
6. **同步改完所有引用**：新增／調整唯一共用實作、逐一接回每個使用頁面，移除已證明完全重複的舊流程；對隱藏或暫停使用的能力先查能否恢復，不擅自刪除。避免一個功能需要使用者提醒兩三次才能改齊。
7. **以行為驗證**：先執行模組與單元測試，再驗證相同核心的每個配置與頁面操作（包含保存回讀、排序、刪除、權限、響應式）；檢查建置與 CI。不得只改測試字串讓 CI 變綠；必要時補測真正的使用者操作。
8. **報告事實**：逐項列出已實際提交的檔案、原本重複的能力如何收斂、保留與恢復的舊功能、全部受到影響的呼叫端、測試結果及仍待處理的項目。沒有通過就明言未通過。

## 完成條件

- 同一種功能在全專案只有單一責任來源，基本與延伸透過配置運作。
- 使用的是現成模組的原生高階能力，而非只有套件依賴和低階函式轉呼叫。
- 每一個受影響頁面及特殊模式已核對，舊功能不因無直接引用而被誤刪。
- 編輯體驗與資料／演算法保持相容；在禁止修改資料庫的任務中 **資料庫零變更**。
- 具備可驗證的 Git 提交與 CI／行為測試結果；未完成項目不得宣稱完成。
