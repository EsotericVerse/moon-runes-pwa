# LOC 物件導向與現成模組深度整合

## 最高優先約束：先核實、先授權、現成能力優先

1. **零未授權寫入。** 先唯讀確認現況、依賴、受影響呼叫端、風險及現成模組功能，提供方案與完整變更範圍，取得使用者明確同意後才可更改程式碼、測試、設定、規範、文件、資料庫或部署。發現額外需求必須先停止並報備；詢問、檢查、驗收、僅說「繼續」不等於額外修改授權。只有使用者明確指定的當次範圍可以執行。
2. **預設不得另外打造功能程式碼。** 優先使用現成穩定的 React／Next.js 模組、SDK、套件及原生高階物件，直接組合既有共用核心；不能複製相同 code 到另一處或另建同質 .mjs／.js／.jsx、Adapter、Wrapper、Hook。無現成／既有能力可滿足時，先提出核實依據、替代方案、必要的最小手工範圍與後續維護成本，經使用者同意才能新增。
3. **物件共用不等於全部載入。** 基本物件單一實作，按使用場合動態組合；使用 next/dynamic、import()、React.lazy 等原生能力按需下載、初始化、掛載，資料與計算也按需執行。實測真實下載、效能、資料查詢與跨頁功能一致性，以穩定、適合、延展性為優先。
4. **預設不建立 Branch、不發 PR。** 只有重要大版本／重大整合的測試階段，先報備用途、測試範圍及風險，經使用者明確批准才可開分支；PR、合併、改寫歷史與刪分支均不得自行進行。直接改 main 仍需事先明確授權。
5. **Git 管理程式碼和必要工程規範，不管理資料庫實際資料與 Schema。** Git Commit、CI、部署、版本回退與備份不構成資料庫修改指示；所有 DDL／DML、欄位、索引、權限、RPC、Migration、清除、同步、還原、備份均需使用者另行提出需求或明確授權。例外僅是 AGENTS.md 第三章：使用者出示 Suno URL 已明確授權新增該 URL 之前可核實的相關作者大綱、完整歌詞、完整 Suno Style、meta_tags；若是既有紀錄，需另外明確表示「更新」，不得因看到 URL 自動覆寫。
6. **逐字元級的完整變更回報。** 每次寫入後逐項交代所有修改檔案、改動前後或完整 Diff、增刪內容、測試與影響；空格、換行、空白行、標點、格式及註解也在內。沒有改動、提交失敗、資料庫未寫入與未驗證部分必須如實說明。不能以「整理」「小修」「CI 成功」概括。
7. **上位規範與執行責任。** 本節與根目錄 AGENTS.md 零章優先於本 Skill 其他段落；使用者負責決策，Agent 負責技術研究、選型、執行、測試及驗證；不擅自跨對話延續寫入、不要求使用者重述既有規範。

## 核心規則

1. **所有開發以 OOP（物件導向）的設計思維為基本原則**：封裝責任、清楚介面、同一能力只有一個實作來源（Single Source of Truth）、透過組合與參數配置擴充功能，禁止把同一個行為複製到各頁面。
2. React／Next.js 中可使用函式元件、Hooks、組合（composition）、props、adapter 與設定物件實現這些原則；**不要求為了 OOP 而改寫成 class**。判準是可重用及可維護，而非檔案副檔名或分檔數量。
3. **能使用現成套件、框架、SDK、React 元件或既有共用模組就先用**。使用前盤點已安裝版本及其官方文件，選擇原生高階 API、現成組合功能、相容與錯誤處理機制，充分利用現有能力；禁止只安裝套件、呼叫少數低階函式後，另寫一套重疊功能並宣稱模組化。
4. **一個核心能力、多種模式／配置**：例如 Editor 依 scope／article／attr 設定決定欄位，圖表依圖型與資料配置擴充，符文基本／延伸頁依顯示模式配置，Admin 與一般頁共用相同操作機制。只有需求確實不同且不能合理配置時，才拆開責任。
5. **不要為了新頁面、新需求或修一個 bug 就新增相同邏輯的 .mjs／.jsx**。先搜尋現有元件、Hooks、服務和所有呼叫端；能延伸既有模組就延伸，能合併重複實作就合併，避免不必要的封裝、代理層與硬編碼分支。
6. **.mjs 是 JavaScript 模組格式，不是應維持的架構單位**。重構時逐一核對檔案職責，能回歸 React／Next.js 現有統合層的重複 UI、狀態或流程就整合；純演算法、資料轉換、跨執行環境共用邏輯可留在獨立模組。不得僅改名或刪檔湊數，更不得改變既有功能語意。

## 極限整合與多物件交互（必須持續適用）

1. **最高優先是不必要的手工新程式碼為零、直接使用成熟現成能力、保留所有既有正確功能並最大化共用核心。** 不得為減少 .mjs 數量而只改名、搬遷、集中成巨型 JS 或新增平行包裝；只有取得具體授權並經依賴和使用情境查核後才能整合、改動或刪除原實作。
2. **Object 不只繼承，還要能交互組合**：同一基礎 Object 支援不同延伸；兩個或更多 Object 可以透過共用介面、組合／策略、Hooks 或既有模組並行，交集也應直接復用現有能力。相同動作只容許一個責任來源，不因交叉情境另造底層。
3. **雙重能力衝突由工程端解決**：同名屬性與方法、狀態管理、`save`／`delete`、權限、事件優先順序、錯誤處理、持久化及回滾的控制權，必須在共用介面明確定義。保留各自的獨特配置與視覺表現，不重複同質實作。
4. **優先深度使用成熟現成模組**：核實套件版本與完整高階 API；能由現有模組完成的 UI、編輯、分頁、解析、匯入、圖表、視覺展示與狀態流程，就不新增自製低階替代。
5. **每個重構批次以數據和行為驗收**：記錄整合前後 `.mjs` 數及真正減少的重複檔案、共用 Object 的實際呼叫端、保留／恢復的功能；執行相關回歸測試、Next.js 建置、CI 與必要的操作測試。禁止為了通過字串斷言而刪掉功能。
6. **跨對話持續尊重規範而非持續擅自施工**：每次開啟或接續 LOC 工作，重新讀取最新 GitHub 主分支的本 Skill 與 AGENTS.md、核對版本與已完成範圍；沒有當次有效授權只能唯讀檢查及擬議方案，不能因上一段對話有未完成工作就自行提交。無法讀取時應如實說明，不得假稱已確認。


## 真正 OOP 與 Lazy Object 的強制實作規格

本節優先於任何「集中函式／減少副檔名就等於整合」的舊說法。**Object 不是 Object.freeze(functions)，也不是 all-in-one 靜態匯入。** 必須封裝職責、明確協作接口、必要狀態及生命週期；可用 React 元件、Hook、Factory、class、策略、Context，但需具有真正獨立的動態載入與延遲初始化行為。

### 每次實作必須符合

1. **程式碼按需下載**：將輕量接口和重型能力拆成可獨立 chunk；使用 next/dynamic、import()、React.lazy 或路由切割。禁止共同入口、barrel、巨型 Object 用頂層 import 把所有實作拉進初始頁面。保留共享邏輯一份，不代表要把所有功能打包同一 chunk。
2. **物件按需掛載**：只有使用者真正開啟功能才建立 Editor／圖表／管理員工具或延伸實例。隱藏 DOM、CSS display:none、僅切換 tab 或只引用動態 import 卻一開始掛載，都不算達標。關閉或路由離開時移除監聽器、取消多餘請求、釋放資源；保留必要緩存須不造成背景執行。
3. **資料按需查詢**：TanStack Query 依功能狀態使用 enabled 與合適的 key，使用真正的後端分頁、游標、上限與必要範圍。顯示 10 筆時不能預先查詢／處理 9,000 筆；圖表運算同樣只對當前需要的資料執行。
4. **動態物件交互**：共用契約可組合多個延伸，每個延伸仍分別懶載入／按需實例化；事件、狀態、權限、save/delete 衝突必須有唯一執行者、優先序及取消方案，不得複製核心邏輯。
5. **零 .mjs 是可達成的方向**：以 Next.js／Node 正確的 ESM 支援逐步統一，但不許只改名、用更多 adapter、建立巨大 JS 檔取代；用依賴圖及真實 chunk 結果判斷是否有改善。
6. **先糾正既有假整合**：重新稽核 HomeBlock、StatisticsFacets、NavigationPreferences、CultureTimelineModel、BlockNoteContent 等靜態聚合是否增加 eager-import，逐一決定輕接口與實作 chunk；Editor 沒通過實際載入／操作驗證前不可宣稱完成，更不能把它當已驗收基底延伸其他功能。
7. **證據驗收**：檢查 Next 建置結果／打包依賴、真實瀏覽器 Network 和效能、初次與互動後下載／運算、非啟用模組是否未查詢、掛載與卸載，以及同一能力在各頁的實際 CRUD、權限、完整資料回讀。只通過原始碼字串斷言、CI 綠燈或數量統計不能過關。

每次新對話先重新讀取最新版 AGENTS.md 及本 Skill，核實最新 commit 與 CI；只有在使用者對本次目標、寫入範圍明確同意後才可實作。Agent 自負技術責任，但不得因此跨越授權。FAQ 暫停、符文最後；一般架構整合不得修改資料庫，Suno URL 的新增入庫遵循 AGENTS.md 第三章單獨授權。

## 執行程序：每次開發與修正都適用

1. **先找已存在的能力**：檢索 repo 全部相同性質實作、套件依賴與所有引用，確認目前可重用的最高階入口及擴充方式。
2. **決定共用核心與設定介面**：界定單一責任來源，讓基本、延伸、特殊頁及 Admin 透過參數、配置或必要的 adapter 共用；不要另外造第二套。
3. **先完整確認全部受影響呼叫端，再僅於授權範圍內修改。** 首頁、搜尋、文化、統計、文章列表、符文、Admin 等凡引用同一能力的地方都必須事先核對。若要維持完整一致性卻需要修改未獲授權的檔案，先列出差異並報備，不得私自延伸修改或留下不明確的半成品。
4. **舊功能先盤點再處置**：標記仍在使用、暫未啟用但可恢復、確定重疊、確定無用途。*無直接引用* 不等於 *應刪除*；可恢復者先保存／整合，只有經核實確為多餘且不影響既有能力的實作才移除。
5. **測試功能而不只驗字串**：檢查編輯、儲存、取消、刪除、排序、權限、資料回讀，以及各使用頁的實際 UI；圖表和符文須核對原本輸出、抽牌規則與呈現。跑相關測試、CI、建置與適當的瀏覽器驗證，失敗需查明原因並修正，不得以部署成功代替驗收。
6. **完整回報所有實際 Diff 與可核實成果。** 明列每個受影響檔案、修改前後逐行差異及每個空格／空白行／格式變更、共用核心、全部呼叫端、真正刪除的重複實作、測試／CI 結果與未完成範圍；沒有寫入或寫入失敗須如實說明，不得用檔案數下降、套件安裝或單頁通過充作全站完成。

## 不可越界

- **此次 LOC 收尾整理不得修改資料庫**：禁止 DDL／DML、資料內容、欄位、Schema、索引、權限、RPC、備份與同步；不可把重構擴大成資料遷移或內容重寫。只有使用者日後對具體資料庫操作另行明確授權，才能重新判斷該獨立任務。
- 遵循根目錄 `AGENTS.md` 既有授權邊界；不可藉「整合」擅自改動作品、文案、已確定的符文定義與抽牌規則。
- FAQ 暫不納入本次整體架構清理；除非使用者另行要求。

**完成標準**：同一能力的行為變更只需修改其共用實作，所有使用情境一致生效；既有功能與使用者的操作習慣保留，測試證明沒有回歸。

## 執行責任與工作優先序

- 使用者是決策者，只需提供方向、成果期待與明確限制，不需要懂或檢查 Coding；Agent 承擔所有實作細節、交付品質、測試及修復，不反向要求使用者指定檔案與寫法。
- LOC 全站收尾先處理首頁、共用介面、Editor、Admin、搜尋、文化、統計、匯入與其他一般功能；符文及遊戲最後。FAQ 目前暫停，資料庫絕對不可寫入、清空、遷移或變更權限、Schema、設定與同步。
- **底層 Object 相同，延伸處理不同**；既有共用核心不得被新開的平行邏輯取代。未使用的舊功能必須先評估能否重新接回，不能隨意刪除。
- 每次交付要用具體 Git 差異與相關端到端測試證實，未完成或 CI 失敗就明確回報，不得將責任推給使用者。
