治理

治理負責讓語言、資料、規則與作品在長期使用中保持一致、可追溯、可修正與可延續。穩定的是框架，不是語言。

一、治理定位

LOC 是語言系統框架，不是教義，也不要求使用者接受特定人生觀。治理處理的是 representation、relationship、scope、lifecycle、provenance、rights 與 boundary：誰負責什麼、資料從哪裡來、哪些內容可以公開、變更如何留下歷史，以及衝突如何被處理。

治理觀點可以不同，但邊界、權責、來源與歷史不能含糊。

二、兩種治理

System Governance

  • 資料權責與母資料優先序。
  • 命名、版本、來源與 Canon 狀態。
  • 功能邊界與跨域關係。
  • 公開、隱私、權利與 publication gate。
  • 異議、review、supersede、withdraw 與歷史留痕。

Personal Governance

個人可以用 LOC 回顧自己的語言、價值、界線、選擇與責任，形成自我治理。這是可被分享與比較的方法，但不會自動變成所有使用者必須採用的規則。

分享方法，不輸出服從。

三、核心原則

  • 中立：不預設政治、宗教、文化、道德或個人價值為唯一正解。
  • 尊重：不同意不等於錯誤；異議進入 review，而不是直接刪除。
  • 界與域：明確定義 scope、ownership、permission、responsibility 與交界。
  • 身分平等：職稱、地位、信仰或角色不會自動取得更高真值。
  • 脈絡適用：舊版本不等於錯，新版本也不等於永恆正確。
  • 多重描述：同一節點可以存在不同 interpretation 與 relation。
  • 可追溯：新增、修改、刪除、異議、發布與撤回都應留下歷史。
  • Evidence before Canon：AI 推論、相似度或單一資料點不能直接升格 Canon。
  • 第一人稱經驗權：人生事件與自身狀態以本人確認優先於系統推測。

四、版本與歷史完整性

LOC 採近似 append-only 的歷史治理：原始事件與原始語句保留；後續 interpretation 可以修正、取代或標記為 historical / superseded，但不反向改寫原始證據。

原始紀錄 → interpretation v1 → interpretation v2 / dispute / supersede → Current View

  • AI rewrite 不得冒充歷史原文。
  • Delete 預設是從 active use 移除，不代表歷史消失。
  • 現行規則可以更新，但舊版本需保留可追溯關係。

五、Create / Update / Delete

  • Create：保存建立者、時間、來源、權責與 initial status。
  • Update：保存 before / after、理由、證據、actor 與版本關係。
  • Delete：預設轉為 archived / tombstoned 等治理狀態，而不是靜默抹除。

六、治理生命週期

Propose / Create → Review → Rights / Evidence / Boundary Check → Accept / Publish → Active → Dispute / Change Request → Re-review → Keep / Amend / Alternative / Restrict / Withdraw / Supersede / Tombstone

治理狀態描述的是 evidence 與 lifecycle，不是思想對錯。

七、資料與功能權責

核心模型是：Authority → Registry → Reference → Consumer。母資料與權威來源優先於衍生檔與展示層；跨域只能 reference、consume 或 propose change，不直接覆寫另一個 domain 的 authoritative record。

  • 原始作者文字與作品本體保留在原始資料責任區。
  • 治理、價值觀、政德風、style-state 與治理 interpretation 由治理層承接。
  • Search、Graph、推演可以消費治理資料，但不能反向成為治理權威。
  • 公開 UI 不需要反覆暴露內部 LOC 編號；編號主要作為資料治理識別。

八、Relation / Graph 治理

  • semantic similarity 只能選 seed，不能自行創造 canonical edge。
  • relation 必須保留 source、target、type、direction、source refs 與 evidence status。
  • 不同 relation 可以並存；錯誤 relation 應修改、redirect、dispute 或 withdraw，而不是抹除歷史。
  • private relation 不因同步而自動公開。
  • Graph node 是權威資料的 reference，不反向取代原始來源。

九、月之符文治理

月之符文的核心語義與 Grammar 以母資料為最高優先來源。符文提供語言，不提供權威；抽牌提供入口，判讀仍需回到問題脈絡與現實證據。

  • 單卡：符文本義 + 卡牌方向 + 月相交互。
  • 雙卡：因 + 果 + 月相交互。
  • 三卡：源 + 轉 + 合 + 月相交互。
  • 五卡：過去 + 現在 + 未來顯化 + 周圍環境 + 自己心境 + 月相交互；不是 2+3 拼接。
  • OW3gs：先讀 7–11 今模組，再回看 1–6 古模組，最後套月相交互。
  • 符文交互限定沙盒；月相交互只作低權重時間修飾。
  • 醫療、法律、工作、合約、金錢與他人意願等現實事項，以現實證據與程序優先。

十、月之符文治理設計補充

Equal Access — 平等使用

  • 不因職業、地位、階級、信仰或特殊身分改變基本符義。
  • 不存在天然擁有更高解釋權的使用者。
  • 使用者可以不同意某個解讀，最終判斷權仍保留給使用者。

66 結構的治理成熟

66 符文的成熟不只來自數量固定，也來自語義責任分割：靈魂／連結分開，自我狀態與關係狀態不混用；「界／域」提供 boundary / domain language；礦物組把價值、資源、物質條件與交換帶回現實層；「悟」則描述理解後的修正與適應。

Stable Rune Framework + Mutable Context / Relation / Interpretation → Governed Change

允許變化，但不失去結構。新的理解應透過 context、relation、version、evidence 與 history 被記錄，而不是任意改寫母資料。

Self-Governance, not Rule by Divination

抽籤結果是語言輸入，不是命令：Random draw → governed rune meaning → orientation / combination / context → interpretation → user reflection → user decision。

Non-mystical Governance Position

月之符文可以保留「符文」「抽籤」「籤詩」等文化與創作形式，但系統本身不需要假定超自然力量、神授解讀權、身分特權、絕對預言或單一不可反駁答案。

四層成熟

  • Semantic maturity：固定位置、核心定義、組別與四向語意。
  • Structural maturity：八組、抽取、雙卡因果、三卡源－轉－合、五卡與 OW3gs。
  • Application maturity：已有抽牌、小說、歌曲、遊戲、Search、Relation、時期與跨功能使用證據。
  • Governance maturity：平等使用、中立描述、界／域、物質價值、自我治理與使用者最終決策權。

成熟不是已經給出永恆答案，而是已有足夠穩定的規則，可以安全容納新的理解。

十一、內容權利、隱私與公開

資料能被匯入，不代表能被公開；能被分析，也不等於能被全文展示或 bulk export。

公開最小條件：ownership / permission 有效、visibility = public、rights_status = cleared。

  • 私人通訊、未授權第三方內容、review_required 資料不得自動公開。
  • Public Browse 只提供 preview；Public Search 只提供與查詢直接相關的有限結果。
  • 完整第一方 corpus 不應透過匿名公開端點整批交付。
  • display policy 分為 snippet / full / metadata_only。
  • 搜尋、分類、Graph、RAG 與推演可以在授權範圍內使用完整內容，但展示層仍受公開規則限制。

十二、自我治理

自我治理不是道德審判，也不是把目前版本變成永恆正解。

回顧 → 比較 → 發現變化 → 理解當時脈絡 → 辨認自己的域與他人的域 → 修正 → 留痕 → 承擔選擇 → 前進

拿過去的自己當資料，不拿過去的自己當枷鎖。

十三、治理語言的變化

治理語言目前可觀察到這條轉移：

外部劇本／防衛 → 權責辨識 → 界線與位置 → 等待、重建與接受未知 → 界線內化 → 自由與選擇 → 自我治理、收尾與航向

這不是「早期錯、後期對」，而是治理焦點與語彙在時間中的變化。歷史使用過的「底線」保留；現行治理更偏向「界／域／domain boundary／scope／ownership／permission／responsibility」。

十四、治理完成的判定

任何功能要宣稱治理完成，至少要回答四層：

Principle → Policy → Executable Control → Evidence / Audit Trail

  • 是否有明確 domain / ownership。
  • 是否支援 Create / Update / Delete。
  • 是否保留 before / after / history。
  • 是否有 dispute / review。
  • 是否有 rights / publication gate。
  • 是否有 provenance。
  • 是否能 supersede 而不重寫歷史。
  • 是否把推論與 Canon 分離。

十五、治理文件為什麼獨立存在

治理是特殊層。不是每一個功能都因為有資料或統計就應新增獨立頁面；治理需要獨立頁，是因為它本身負責規則、權責、版本、邊界、變更依據與可稽核性。

governance.html 因此是治理的正式公開入口。治理相關正文以此頁為主；Markdown 只保留確實需要的技術規格、schema、API、資料結構或機器治理文件。

政德風

政德風是已整理完成的固定說明文件。它記錄王政德如何把經驗、感受、判斷、界線、責任與選擇逐步整理成可再次使用的語言。

一、核心公式

把經驗整理成可以再次使用的語言。

看見情境 → 拆解預設 → 確認權責 → 建立界線 → 保留選擇 → 做出取捨 → 回到可治理的日常。

二、治理內容與風格狀態分開

Governance Content

回答「相信什麼、怎麼判斷、界線在哪裡」：價值判準、主權、權責、尊重、界線、自我治理、收尾與航向。

Style State

回答「同一個意思，在某個時期會怎麼說」：句子長短、感性／理性比例、意象密度、反問與反轉、克制度、外部拆解或內部治理。

價值可能延續，但說法會隨時期改變，因此兩者不能混成同一資料。

三、長期並存的理性與感性

感性書寫多從個人經驗、身體感受、等待、失落、孤獨、愛與希望出發，常使用月光、微光、風、夜晚、道路、月台等意象。

理性書寫則直接提出命題、界線、責任與判斷。這些文字後來也大量進入歌曲，使部分作品形成近似「文章被音樂化」的表達。

四、三種論述方向

  • 思辨論述型：理解問題、重框、提出觀點。
  • 治理宣言型：面向自己，從看見問題走到確認責任、建立界線、做出選擇。
  • 勸戒論述型：面向他人或群體，提出提醒、責任與後果。

五、核心治理模組

  • 價值與判準：用自己的價值標準判斷，而不是因權威或群體劇本直接接受。
  • 主權與選擇：保留回答、拒絕、失敗、修改與重新決定的權利。
  • 權責與界線：先確認位置、責任與義務，再決定是否介入。
  • 防衛而不失控：必要時停止被侵入、被定義或被拖進不屬於自己的責任。
  • 幽默與反轉：以短句、反問、雙關或現實落差快速重設語境。

六、代表治理句

  • 「價值觀的價值。」
  • 「我允許錯誤發生，只要錯的有價值。」
  • 「免錢的最貴。」
  • 「我不跟你走劇本。」
  • 「你在玩話術，我在改規則。」
  • 「我不是要當王，我只要系統能跑。」
  • 「慈悲不是投降。」

七、現行階段：治理自己

目前重心已從「取得自由」移到「自由之後如何治理自由」：整理過往、完成未竟之事、確認責任、斷捨離、重新歸檔並選擇下一段航向。

從「拆別人的劇本」逐漸移向「治理自己的日子」。

八、時期與風格變化

政德風的主要時間座標是時期，而不是直接用年齡切分。年齡只能作為時期與歷史語料之上的次級 View。

目前可概括為：探索與試錯 → 感性／關係敘事 → 界線與治理轉折 → 等待與重建 → 界線整合 → 自由與前行 → 自我治理。

九、ERA 細部變化

  • P1：探索與試錯，語言尚未穩定。
  • P2：重啟與格式形成，微光、夜晚、月光與孤獨等意象建立辨識度。
  • P3：微月光與關係敘事，自省、陪伴、愛與界線開始並存。
  • P4：現實壓力與治理轉折，界線、現實選擇與治理宣言明顯上升。
  • P5：人生月台與語言重建，轉向等待、看清現實、允許暫停與保留希望。
  • P6：順其自然與界線整合，界線從防衛工具逐漸內化為日常治理。
  • P7：自由的風，語言轉向自由、選擇、可能性與前行。
  • P8：自由的月／治理自己，整理、收尾、責任、歸檔與航向成為核心。

ERA 的風格判斷是可更新的 interpretation；歷史原文與當時語境仍保留，不因後期分類而被改寫。

十、跨媒介證據

政德風不只存在於單一文章。歌曲、文章、生活文字、Reels、多媒體與 ERA 都可能成為證據。同一概念可以由短句形成歌曲，再擴寫為文章，最後轉成影音或其他表達。

原始文本仍屬原始資料來源；治理頁只保存經確認的治理與風格 interpretation，不反向覆寫原文。

十一、政德風治理規則

  1. 原始語句保留原文，不以後期說法覆寫。
  2. 代表句與後設解讀分開保存。
  3. AI 重寫不能冒充歷史原文。
  4. 風格推論需要來源與 confidence。
  5. 不因一句話「很像政德風」就自動升格為核心原則。
  6. 現行階段可以更新，歷史階段不得被新版本抹除。
  7. 自我治理是版本管理，不是道德審判。

十二、治理頁的角色

政德風是治理主頁中的固定個人治理文件；搜尋「政德風」時應優先顯示這份正式說明，再列歌曲、Threads、文章與其他語料作為證據。
