## 1. 上位分類

本文件依 LOC Canon 1.2 的責任邊界整理：

- **LOC／月典（Luna Codex）**：模組化語言框架。負責分析拆解、組織彙整、搜尋、模組化與治理；不是月之符文本身，也不替使用者決策。
- **LunaRunes／月之符文**：符號式語言與情景具體模擬的參照實作。它從最基本的符文特質種子與交互關係開始，再以模組組合描述更複雜的脈絡、時期、文化與情景。
- **OW3gs**：`Oscillation World 3 Grounds System` 的歷史簡稱／別名；Current 以「三維震盪模板」描述其作者特化方法。它現行歸屬德之符文（De／Rune 0）的作者方法／治理脈絡，也是 LOC 模組化方法的重要來源案例。
- **政德風（Zhengde Style）**：Lucas Oscar Wang 政德的個人文化／作者語言風格，不等同 LOC，也不等同 LunaRunes 的共同規則。
- **德之符文（De／Rune 0）**：Author Governance 的作者文化與治理紀錄錨點；不屬於 66 符抽取池、不參與抽牌、沒有卡面。OW3gs、政德風及其文化衍生物可在此留下作者方法與文化 provenance，但不因此改寫 66 符 Canon。

因此資料可以跨分類關聯，但不可互相取代：LOC 是框架；月之符文負責符號式語意與情景模擬；OW3gs 是作者特化模板；政德風屬作者文化；作者方法與文化衍生物另以德之符文建立 provenance／文化紀錄。

## 2. 方法起點：不替人決定是非

月之符文不是為了特立獨行而反對流行，也不是為了順應流行而把當下道德直接寫成系統答案。作者的基本態度是：**無權替其他人預先決定是非。**

因此 LunaRunes 從最基本的特質種子開始，以交互關係與組合增加解析度，而不是增加替使用者裁決的權力。系統應忠實保存符文、位置、四向、時間、脈絡與組合關係；價值判斷與行動責任仍屬使用者。

**治理句：沒有預設的是非，只有忠實的紀錄與可追溯的組合。**

同一篇文字、同一首歌曲、同一事件，由不同的人在不同時間接觸，其時間基準、Phase、關係與 Context 都可能不同。符文演算法只負責提供當下條件下可供參考的可能情景；理解、選擇與責任仍屬使用者。

**治理句：符文演算法的演化，只增加可能情景的解析度，不增加替人決定的權力。**

## 3. 從最小種子到複雜模型

月之符文的「符號式語言」不是把每個特殊情況都變成一條特殊規則，而是用有限、可辨識的基本分類掌握複雜原則：**基本分類保持簡單，複雜性由組合產生。**

- **單卡**：基本特質種子／最小語意單位。
- **雙卡**：最小交互模型，描述兩個特質之間的關係、因果或脈絡。雙卡本身不替交互結果標記道德上的正誤。
- **三卡**：`源－轉－合`。在既有關係之上加入一個主要變數／轉折，透過時間基準點、時期／Phase 與作用範圍推論可能性。它不是單純「找適合時機」，而是設定推論座標。
- **五卡**：把雙卡的關係／因果與三卡的源轉合進一步組合，形成有限複雜度的文化／情境描述。變數仍保持可辨識，以免模型因複雜而失去可解釋性。
- **OW3gs 11 卡**：作者特化的三維震盪模板，把多組關係、時期與特質放入同一情景中整合。11 卡是 OW3gs 的保留實作；其他使用者可建立自己的牌數、位置、Grammar 與註解，只需清楚標示 Scope 與來源。

代表鏈：

`單卡（Seed） → 雙卡（Relation / Context） → 三卡（Period + Context / 源轉合） → 五卡（Culture / 有限複雜情境） → OW3gs 11 卡（三維震盪模板／完整情景）`

所有高階結構都應可回溯到單卡的基本特質與雙卡的基本交互。這條鏈本身就是「以實例才能更新論點」的代表案例：如果沒有一個可實際組合與檢查的模型，就不應只憑抽象說法把新原則寫入 Canon。

## 4. 三個分析基底與進階維度

今日可用三個分析基底／三個維度來說明 OW3gs 的方法結構：

1. **一維：關係（Relation）**——從單卡、雙卡建立特質之間的交互與 Context。
2. **二維：時期（Period / Phase）**——把同一關係放入不同時間基準與階段，觀察狀態如何轉變；三卡源轉合是明確實例。
3. **三維：整合特質／完整情景（Integrated Trait / Context）**——把多組關係與時期疊加，形成可分析的完整情景；OW3gs 11 卡是作者特化實例。

在進階分析中，**時、辰、緣不得合併成同一欄位或概念**：

- **時**：時間基準、時序與距離。
- **辰（Phase）**：所處階段、位置與狀態相位。
- **緣（Karma）**：關係形成、交會與連結條件。

它們可以共同影響推演，但回答的是不同問題，不能互相取代。

## 5. OW3gs 名稱治理與歷史來源

最早正式定義的全名是 **Oscillation World 3 Grounds System**；**OW3gs 是其歷史簡稱／別名**。作者另以「**三維震盪模板**」作為自己的中文別名與 Current 說明。今日語意上更適合稱為「模板」，因為它是一組可套用、可組合、可重算的三維分析結構，而不是必須獨立存在的上位框架。

它形成於作者採用「王政德／政德」這一 Current 名稱之前，也早於後來使用 `lo3rwang` 作為公開識別，因此名稱不能用後來的身份回溯重寫。

Current 命名治理：

- 歷史正式名稱：**Oscillation World 3 Grounds System**。
- 歷史簡稱／別名：**OW3gs**。
- 作者中文別名：**三維震盪模板**。
- Current 類型用語：**Template／模板**。
- **不得**把 OW3gs 回溯改名或反向解釋成 `LOW3GS`、`LOW 3 Grounds System` 或任何以 `LOW` 為前綴的名稱。
- `lo3rwang` 是後來形成的作者公開識別，並非 `LOW` 的縮寫。作者刻意避免用 `LOW` 統一縮寫，因為英文 `low` 具有「低」的既有字義，會造成不必要的語感與語意偏移。
- OW3gs 現行歸屬 **德之符文（De／Rune 0）** 的作者特化方法／治理脈絡，但 Current 歸屬不得覆寫其更早的歷史正式名稱與形成時間。
- 「三個分析基底／三維」是今天用來整理 OW3gs 方法的概念說明，與正式名稱中的 `3 Grounds` 相容，但不應反向製造其他 backronym。

這條治理符合 LOC 的歷史原則：**新的理解可以更新 Current 解釋，但不能用新的名字重寫舊的歷史。**

## 6. OW3gs 與 LOC／月典的前因後果

LOC／月典不是先出現再發明 OW3gs；方向相反。Oscillation World 3 Grounds System／OW3gs 的分析、組合與實際使用經驗先存在，之後在整理這些方法時，逐步抽出可共用的模組、分類、治理、搜尋、歷史與演化原則，形成 LOC。

歷史／方法論鏈：

`Oscillation World 3 Grounds System／OW3gs 的實際分析與組合經驗 → 方法整理 → 抽象化／模組化 → LOC／月典`

因此 LOC 可以在概念上被理解為比 OW3gs 再往上一層：不只分析情景，而是開始**治理分析方法本身**，處理不同模組如何命名、分類、連接、版本化、搜尋與演化。若以維度比喻，這可以說是「第四層／四維」；但 **`4gs` 從未被建立為必要的正式名稱，Current 也不新增 `4gs` 模組**。LOC 就是這個抽象化後的正式框架名稱。

## 7. 為什麼是 11

OW3gs 的 11 不是單純容量數字，而是完整語意結構。

11 為質數，在本方法中被採作一個不可平均拆成相同小單位、但可由內部模組重新組合的完整抽牌單位。其價值不在神秘數字宣稱，而在實際結構：11 張足以同時保留成因／場域、核心判定與綜合情景，又仍維持單次 Draw Session 的可讀性。

因此可用一句話表示：**11 不是容量，而是結構。**

## 8. OW3gs 雙層與綜合讀取

OW3gs 使用 11 張不重複符文；每張抽牌保留符文、位置與四向。

- **1–6：Context／因的描述層**：建立成因、背景、條件、來源、資源、阻力、外部擾動與顯著主題。不是六張逐句串接。
- **7–11：核心五卡模組**：作為主要情景判定／參考層。依現行 Grammar 的五卡責任進行綜合，再把 1–6 真正相關的資訊帶回。

OW3gs 的輸出不是 11 個單卡解釋相加，而是：

`11 張符文 → 位置／四向 → 模組關係 → 綜合情景 → 明確語意／關鍵字 → Search / KM / 延伸體系`

因此 OW3gs 已可產生適合關鍵字搜尋的明確語意，也能成為其他符文延伸體系的結構化輸入。

## 9. 月相交互的現行邊界

卡片月相與真實月相資料仍保留，但月相交互只屬時間情境的低權重微調／保留精細化層，不應覆蓋符文本義、位置、四向或 OW3gs 核心綜合結果。

更深入的月相交互理論上可進一步區分高度相似的情景，但目前不增加此層的演算法複雜度。OW3gs 在未深化月相交互的狀態下已是完整可用模板。

## 10. 與 LOC2 卡片遊戲的歷史邊界

Historical LOC2／Semantic Playground 的卡片遊戲規則**不使用四向面向**。遊戲可共享 66 符、群組、關係與模組化規則，但不因 OW3gs 使用四向而把面向重新加入遊戲基礎規則。

此名稱只作 Historical／既有資料辨識，不恢復已廢止的 LOC1–8 Current 架構。符文文學使用 OW3gs 的四向與綜合情景，是符文規則的延伸應用，不是 Historical LOC2 規則搬移。

## 11. 延伸體系的資料分層

符文作品至少保留兩層 Rune Data：

1. **Draw Layer／創作來源層**：作品若由抽牌生成，保存原始符文、順序、四向、draw mode 與 provenance。OW3gs 為固定 11 張。
2. **Content Analysis Layer／內容分析層**：完成作品後，再依 LunaRunes 語意分類分析作品實際呈現的符文語意。數量不必等於 11，也不把內容分析結果冒充原始抽牌。

兩層重疊與差異本身可用來觀察「符文種子 → 完成作品」的語意轉化。

## 12. 符文文學：OW3gs 綜合情景生成

符合 OW3gs 的文學作品正式歸入：

**Rune Symbolic Extension: Literary／符文延伸體系：文學**

生成關係為：

`OW3gs 11 抽 → 綜合情景／關鍵字 → 人物關係、衝突、轉折與情緒起伏 → 文學具象化`

符文不是逐張指定十一個段落。11 張共同限制語意空間，綜合模組負責起伏與關係；文學創作再把抽象語意轉成場景、人物、事件、對白與意象。

### 代表範例：《凌晨兩點四十七分》

Record：`RLIT-20260916-001`

原始 OW3gs：

1. 鏡・半正位
2. 月・逆位
3. 果・半逆位
4. 花・正位
5. 誤・半逆位
6. 空・半正位
7. 語・正位
8. 心・半正位
9. 光・正位
10. 愛・逆位
11. 緣・半正位

情景不是「鏡寫第一段、月寫第二段」；而是由整組建立夜晚、映照、未完成的過去、逐漸萌生的關係、誤讀修正、空缺、表達、內心變化、看見、愛的阻力與持續靠近。

作品以凌晨自助洗衣店、兩個不同形式的孤單、固定相遇與逐漸期待，把綜合語意具象化；洗衣機的旋轉進一步形成 `Loop ≠ Repeat` 的文學意象：看似回到原位，但每一輪狀態已經改變。

這篇因此是目前 **「OW3gs 11 抽 → 綜合情景 → 符文文學」的標準應用範例**。

## 13. 德之符文與作者文化紀錄

《凌晨兩點四十七分》的符文來源分類仍是「符文延伸體系：文學」；若作品同時使用政德風／作者文化進行再創作，則另外建立 **De／德之符文 Author Culture relation**。

治理原則：

- 符文延伸體系回答「它是什麼作品／如何由符文生成」。
- 德之符文回答「它與作者文化、政德風、OW3gs 作者方法有什麼關係」。
- 同一作品可以同時存在兩種 relation；不得因屬作者文化而從符文文學移除，也不得把作者文化自動提升為所有使用者共同規則。

## 14. 模組化代表鏈

OW3gs 可作為 LOC 基本模組化的代表：

`LunaRunes Seed → Relation / Context → Period / Phase → Integrated Trait / OW3gs Context → Keywords / Search → Extension → Work → Content Analysis → KM / Culture`

若作品屬 Lucas Oscar Wang 政德的個人文化衍生：

`Work → Zhengde Style / Author Culture → De Rune record`

LOC 負責讓上述模組可以被分類、連接、搜尋與治理；LunaRunes 提供可具體模擬的符號式情景；OW3gs 保存作者特化的三維震盪模板；政德風保留為作者文化，不與通用框架混為一體。
