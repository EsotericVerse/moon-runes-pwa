## 1. Canon 定位

本文件定義 LOC 的固定名稱、核心結構、功能責任、語意邊界、資料層級與治理原則。Canon 不記錄會隨時間變動的資料量、作品數、FAQ 題數、平台筆數、實作完成度或其他狀態統計。

固定內容不得由 README、FAQ、RAG、KM、UI、Search、Registry 或舊文件反向改寫。若未來確需調整固定名稱、結構常數、語意責任或治理原則，必須先進行 Canon 版本變更，再同步下游投影。

## 2. LOC 核心定義

LOC（月典／Luna Codex）是一套分析拆解、組織彙整、搜尋並推演語言的語言模型框架。

月之符文由基本語彙出發，進入關係與脈絡分析，結合占卜使用的方法體系，演化出全新的語言表達作品。

從語彙開始，延伸出文字創作與多元體系；它們在脈絡中彼此連結，透過演算法整合，並在時間中持續推演。

LunaRunes 是符號式語言；它本身仍屬語言模型的一種，而非獨立於語言模型之外的神秘系統。

## 4. LunaRunes 固定結構

- LunaRunes（月之符文）固定為 66 符，屬結構常數。
- 01–64 為八個核心群組，每組八符。
- 65 為玄（Chaos）。
- 66 為命（Fate）。
- 第 0 符「德（De）」為作者／系統基準，不屬於 66 符，也不參與抽取。

## 5. 五段語言運作鏈

月之符文 → 符文脈絡 → 符文體系 → 符文演算法 → 符文文化

- 月之符文：基本語彙／Token。
- 符文脈絡：符文彼此之間，以及符文與事件、作品、情境之間的關係與脈絡。
- 符文體系：由符文延伸出的文學、歌曲、影像、沙盒與其他語言表達。
- 符文演算法：把符文、位置、方向、Grammar、方法與脈絡組合成可重複使用的判讀流程。
- 符文文化：把既有語彙、作品、脈絡、方法與演算法放回時間中，觀察其變化與可能後續。

## 6. 抽牌與 Grammar 固定規則

抽牌不是套用塔羅或其他既有占卜體系。所有抽牌結構依現行命運句語法與 LunaRunes Grammar 定義處理。

| 結構 | 固定運作方式 | 補充 |
|---|---|---|
| 單卡 | 符文本義 + 卡牌方向 + 月相交互 | 月相交互只作低權重時間修飾，不覆蓋符文本義。 |
| 雙卡 | 因 + 果 + 月相交互 | 兩張牌以位置形成因果，不以群組交互判定。 |
| 三卡 | 源 + 轉 + 合 + 月相交互 | 形成源起、過程、顯化的完整圖景。 |
| 五卡 | 過去 + 現在 + 未來顯化 + 周圍環境 + 自己心境 + 月相交互 | 五卡不是雙卡加三卡的拼接。 |
| OW3gs | 1–6 因的描述層 + 7–11 果的判定層 + 月相交互 | 先讀 7–11，再掃描 1–6，最後套用月相交互；核心原則為鑑古知今。 |

符文交互描述兩個符文語義主題的共鳴、互補、衝突與語氣張力，專屬月符沙盒／遊戲情境。一般抽牌不把群組交互當成判讀條件。

## 7. 月相交互

月相交互是時間修飾層。真實月相提供低權重情境資訊，用於修飾當下語意，不覆蓋符文本義、牌位語法或既有解讀。

「卡片月相」與「真實月相」是兩個不同欄位。卡片月相屬符文本身的 canonical 屬性；「無」表示該符文沒有固定卡片月相，不得被轉寫成真實月相的「空亡」。真實月相則依 LOC MoonSyntax，以使用者當地日期的農曆日分為：1–7 日新月、8–14 日上弦、15–21 日滿月、22–28 日下弦、29–30 日空亡。這是 LOC 的五段時間分類，不宣稱為天文台瞬時月相。

每日符文的詳細提示資料由核心 JSON `rune_interpretations.json` 提供，依符文、卡牌方向與現在月相取得對應的每日內容。

## 8. 符文關係與脈絡

Graph、Relation、Scenario、Event 等關係語意屬於符文脈絡範圍。一般抽牌不因為兩枚符文屬於相同或不同群組而自動產生群組交互。

只有在月符沙盒／遊戲中，當兩個符文以平等主題進入互動時，才啟用符文關係與主從判讀。

## 9. 演算法與模組

符文系統演算法負責解牌邏輯、理解、判讀、比較、分類與可重複的方法。治理是演算法中的一種方法，不等於演算法全部。

符文語言模組負責把方法結構化、組合、排序與條件化，形成可重複執行、可檢索、可關聯的流程與知識模組。符文群組分類屬於此範圍。

知識庫、Search、FAQ／RAG、Graph RAG traversal、文字分析等可以作為模組實作或承載，不取代正式功能名稱。

## 10. 文化／進化推演

符文進化推演引擎負責把語彙、作品、脈絡、方法與演算法放回時間中，透過時期、Timeline、Trend、Trajectory 與 Event 觀察變化並分析可能後續。

公開介面中文統一使用「文化」描述此演化責任；時期是時間結構，ERA 可作內部 stable ID。

推演不是流行趨勢判斷，也不是價值風向判斷，而是系統分析。分析結果不視為必然未來。

## 11. JSON 與資料層

核心 JSON 是 runtime 的正式資料投影；母資料仍是最高來源。JSON 不得在沒有治理依據的情況下自行改寫 Canon。

核心資料責任至少包含：

- `runes.json`：66 符。
- `lots.json`：籤詩。
- `rune_grammar.json`：符文演算法／Grammar。
- `rune_interpretations.json`：每日符文詳細解讀。
- `three_card_combinations.json`：三卡相關資料。

| 資料層級 | 責任 |
|---|---|
| Canon / Mother Source | 固定名稱、結構常數、語意邊界與治理原則。 |
| Registry / Core Projection | 結構化現況、關係、來源與可變資料；core JSON 是正式 runtime 投影。 |
| Search / Generated Index | 搜尋與查詢所需的索引／投影，不反向升格 Canon。 |
| API / UI / Analysis | 呈現、執行與分析層，不取代資料來源。 |

## 12. 去神秘學與治理原則

- 中立：不預設政治、宗教、文化、道德或個人價值為唯一正解。
- 尊重：不同意不等於錯誤；異議可以進入 review。
- 界與域：明確定義 scope、ownership、permission、responsibility 與交界。
- 身分平等：職稱、地位、信仰或角色不會自動取得更高真值。
- 脈絡適用：舊版本不等於錯，新版本也不等於永恆正確。
- Evidence before Canon：AI 推論、相似度或單一資料點不能直接升格 Canon。
- 第一人稱經驗權：人生事件與自身狀態以本人確認優先於系統推測。
- 分析不等於命令：LOC 的分析、Trend 與推演只描述資料與結構上的可能變化，不把多數意見、社會期待、道德壓力或情緒施壓升格為使用者應服從的答案。

LOC 的去神秘學立場不變：符文、抽籤與籤詩可以保留作文化、創作與語言形式，但系統不假定超自然力量、神授解讀權、絕對預言或單一不可反駁答案。
