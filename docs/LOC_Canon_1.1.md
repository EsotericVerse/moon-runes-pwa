本文件定義 LOC 的固定名稱、核心結構、功能責任、語意邊界、資料層級與治理原則。Canon 不記錄會隨時間變動的資料量、作品數、FAQ 題數、平台筆數、實作完成度或其他狀態統計。

## 2. LOC 核心定義

LOC（月典／Luna Codex）是一套分析拆解、組織彙整、搜尋並推演語言的模型化語言框架。

LOC 提供模組化、脈絡、搜尋、文化與演算法等框架能力，並內建月之符文（LunaRunes）的簡單語意判定規則作為參照實作。目的不是要求所有語言採用月之符文分類，而是示範各種語言與文化都可以建立簡單、可解釋、可治理的分類方式。

LunaRunes 是依 LOC 原則建立的符號式語言。LOC 提供分類、脈絡化、模組化與治理方法；LunaRunes 以實際語意判定、例外與文化案例驗證這些方法。兩者相輔相成，但 LunaRunes 的具體符文歸屬不自動成為其他語言或文化的共同規則。

月之符文是種子，但不是使用門檻。

## 4. LunaRunes 固定結構

- LunaRunes（月之符文）固定為 66 符，屬結構常數。
- 01–64 為八個核心群組，每組八符。
- 65 為玄（Chaos）。
- 66 為命（Fate）。
- 第 0 符「德（De）」保留，但不屬於 66 符抽取池，也不參與抽取。
- 德是 Author Governance 的個人風格治理分類，不因文字出現「德」、一般道德詞彙、作者姓名或其他人的姓名而自動歸德。
- 德的作者治理保留詞可由作者維護；現行明確項目包含：微月光、人生月台、斜教、OW3gs。

## 5. 五段語言運作鏈

月之符文 → 符文脈絡 → 符文體系 → 符文演算法 → 符文文化

- 月之符文：基本符號語彙與 LunaRunes 語意定義。
- 符文脈絡：符文與文字、事件、作品、情境之間的語意關係與判定理由。
- 符文體系：由符文延伸出的文學、歌曲、影像、沙盒與其他語言表達。
- 符文演算法：以可解釋的原則完成文章分類與抽牌判讀，不等同單純關鍵字搜尋。
- 符文文化：把既有資料放回時期中，觀察歷史形成、延續、轉變、分化、消退、回返與擺盪；不負責預測未來。

## 6. 抽牌與 Grammar 固定規則

抽牌不是套用塔羅或其他既有占卜體系。所有抽牌結構依現行命運句語法與 LunaRunes Grammar 定義處理。

每張牌是一個獨立 Random Event：同一次隨機事件同時決定符文與方形卡牌位向。一次 Draw Session 內，符文候選池逐張縮減且不可重複；位向可重複。不得把符文與位向拆成兩次獨立的語意隨機事件，也不預先批次產生整個牌陣。

| 結構 | 固定運作方式 | 補充 |
|---|---|---|
| 單卡 | 符文本義 + 卡牌位向 + 月相交互 | 月相只作最後的低程度時間修飾，不覆蓋符文本義。 |
| 雙卡 | 因 + 果 + 月相交互 | 兩張牌建立基本因果關係。 |
| 三卡 | 源（因） + 轉（意外因素） + 合（果） + 月相交互 | 源起、變因、顯化；合不是絕對命運。 |
| 五卡 | 兩張過去成因 + 一個意外變化 + 兩張現在狀況 + 月相交互 | 結構為雙卡 + 單卡 + 雙卡；現在狀況是當下延伸的可能結論。 |
| OW3gs | 源兩張 + 轉兩張 + 合兩張 + 五卡治理／建議 + 月相交互 | 1–6 為因的描述層，7–11 為果的判定／建議層；先建立因果脈絡，再作治理建議，核心原則為鑑古知今。 |

解牌是語義組合，不使用數值權重公式。位向描述當次語意狀態，不把符文轉成宿命結論。月相交互最後加入，只作時間情境修飾。

## 7. 月相交互

月相交互是時間修飾層。真實月相提供低程度情境資訊，用於修飾當下語意，不覆蓋符文本義、牌位語法或既有解讀；「低程度」是解讀優先序，不要求轉成數值權重。

「卡片月相」與「真實月相」是兩個不同欄位。卡片月相屬符文本身的 canonical 屬性；真實月相屬當下時間情境。任何月相資料都不得反向改寫符文 Canon 定義。

## 8. LunaRunes 簡單語意判定

符文演算法的文章判別不是單純 Keyword Search。關鍵字只產生候選；實際歸屬必須依完整詞／詞組的實際語義與 LunaRunes 定義判斷。

基本流程：

完整詞／詞組辨識 → 實際語義判斷 → 符文基本定義 → 語意組合操作 → 少量 Governance 特殊義 → 符文歸屬

目前採用四種基本語意操作；它們是判別方式，不是數值權重：

- **AND｜並列**：多個符文語義在完整詞義中都實際成立，全部保留。例如：時空 → 時 + 空；風向 → 風 + 向；明火 → 明 + 火。
- **PLUS｜增義**：原有語義仍成立，完整組合再增加新的語義維度。例如：天時 → 時 + 緣。
- **OVERRIDE｜專屬完整義**：完整詞已形成專屬語義，依完整義判定，不因內部字元再增加其他符文。例如：時辰 → 辰；清明 → 辰；日月當空 → 明。
- **DEFER｜延後判別**：某些符文定義具有高度特製性，字面命中先不直接歸屬，等待完整詞義判定。日、月為現行代表：日蝕 → 日；月蝕 → 月；日期 → 時；日月表達歲月／一段時期時 → 辰。

原則上，一個詞可以歸屬多枚符文；只有完整詞義形成專屬判定時才不拆分。不得為了追求唯一分類而強迫刪除實際成立的語義，也不得因中文字元出現就自動增加符文。

詞性與句內角色是協助理解語義的資訊，不是把符文永久鎖定成單一詞性的限制。例如空可依語境作名詞或狀態描述，只要空的實際語義成立即可參與判定。

### 時／辰／緣／誤的現行語意邊界

- **時**：時間規則、尺度與時間本身的計量描述，例如日期、幾日、幾月、多久。
- **辰（Phase）**：節氣、時期等具有階段／區段意義的時間描述；不以早晨到晚上等日內列舉作為核心定義。清明、節氣、時辰均歸辰。
- **緣（Karma）**：時間與事件、條件、對象等因素交互後形成的適合時機。遲到、延誤、錯過描述的是相合時機沒有成立，歸緣而非誤；這不表示命定的「沒有緣分」。
- **誤（Error）**：資訊、理解或判斷本身的錯誤，例如誤解、誤判、錯誤資料。不得因「延誤」含有誤字就歸誤。

### 從例外找原則

治理不以建立大型 `keyword → rune` 例外字典為目標。遇到新案例時，優先判斷能否由既有語意操作解決；若多個案例可抽象成同一判別方式，應提升為原則。只有無法由通則推出、且具有穩定完整義的特殊語意，才保留為 Governance 特殊義。

關聯與案例用於發現、驗證與測試原則，不用來窮舉所有符文組合。文章分類結果可以重新掃描與重建，治理原則才是判別依據。

## 9. 治理與演算法

LOC Governance 的實際方法之一，是要求分類方式具有基本、可解釋、可重複使用的語意原則，而不是依賴大量逐筆例外。LunaRunes 是內建參照實作；其他語言、文化或符號系統可以建立自己的分類原則，不需要複製 LunaRunes 的具體符文歸屬。

LunaRunes Governance 負責公開「為什麼這樣判」：基本定義、AND／PLUS／OVERRIDE／DEFER、適用範圍、少量特殊治理義與爭議處理。Algorithm 負責實際執行；Context 呈現判定與理由；Statistics 使用演算法結果；Culture 再依 ERA／時期觀察歷史差異。

Governance 特殊義應維持最小化。德之符文的 Author Governance 是明確的 Scope 特例：作者可以維護自己的穩定風格詞，但這些詞不自動提升為公共 LunaRunes 或其他人的分類規則。

## 10. ERA 與符文文化

ERA／時期以具有持續性、且足以改變分析脈絡的治理、結構、語義或文化變化作為邊界。固定年度只是時間索引，不自動形成新的 ERA。RC 可記錄候選／過渡狀態，但不因存在 RC 就自動建立新 ERA。

LunaRunes 正式 Rune ERA 節點為：14 → 24 → 32 → 42 → 66。40 為 P4.0 RC、64 為 P5.0 RC，保留為轉換歷史，不另立正式 ERA。

Culture 是歷史與文化觀察，不具有預測責任。其觀察至少包含：形成、延續、轉變、分化、消退、回返與擺盪（Oscillation）。新舊 ERA 的符文差異應以符文演算法重新分類後的語意結果比較，而不是直接比較中文字面 Keyword 次數。

## 11. JSON 與資料層

核心 JSON 是 runtime 的正式資料投影；母資料仍是最高來源。JSON 不得在沒有治理依據的情況下自行改寫 Canon。母資料維持唯讀治理，任何 runtime、Search、Statistics 或 UI 投影不得反向污染母資料。

| 資料層級 | 責任 |
|---|---|
| Canon / Mother Source | 固定名稱、結構常數、語意邊界與治理原則。 |
| Registry / Core Projection | 結構化現況、關係、來源與可變資料；core JSON 是正式 runtime 投影。 |
| Search / Generated Index | 搜尋與查詢所需的索引／投影，不反向升格 Canon。 |
| API / UI / Analysis | 呈現、執行與分析層，不取代資料來源。 |

## 12. 治理中立與 Copyleft

- 中立：LunaRunes 有自身分類立場，但不把自身分類、價值觀或文化解釋強迫成他人的必然答案；分析與分類可供參考。
- 客觀與可解釋：治理判定應依公開且可重複適用的理由，不以原作者個人好惡取代判別原則。
- 個人決定權：LOC／LunaRunes 負責整理、分類、關聯與呈現資料；個人的風格定義、價值判斷與最終決定權歸屬個人。
- 內容描述與價值判斷分離：語意分類依資料實際內容處理，不因題材本身具有暴力、黑暗、爭議或其他敏感描述就改寫其語義；內容描述、價值判斷與實際行為指導分別治理。
- Scope：每個文化、Domain、功能與個人治理可以有自己的規則；某一 Scope 的最高解釋原則不得自動提升為其他 Scope 的共同規則。
- Copyleft：允許學習、參考與建立自己的體系；開放不等於放棄作者權益，也不表示所有衍生內容都必須署名或取得許可。當實質沿用 LunaRunes 具有辨識性的內容、資料或整體特質時，應尊重並揭示來源，依其衍生治理處理。
- Audit：只處理 LunaRunes 的引用與實質衍生治理，不是對所有符文體系的審批，也不構成原作者對衍生作品的推薦、認可或背書。任何以原作者名義表示背書，須另有明確授權。

任何人都可以獨立建立自己的符文或符號式語言；單純名稱相同、個別概念相似或一般性參考，不因此自動受 LunaRunes 治理。LunaRunes 只治理自身內容及其實質衍生使用。

## 13. 去神秘學與解讀邊界

符文、抽籤與籤詩可以保留作文化、創作與語言形式，但系統不假定超自然力量、神授解讀權、絕對預言或單一不可反駁答案。

緣的位向只描述當次時機與條件的呈現狀態，不得簡化成「正位＝有緣分、逆位＝沒有緣分」的宿命結論。其他符文亦同：位向修飾狀態，不建立命定論。
