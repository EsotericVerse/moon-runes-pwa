# LOC1 OW3gs Reference Cases

**Status:** Current / Reference  
**Updated:** 2026-09-07  
**Scope:** LOC1 · LunaRunes · OW3gs  
**Purpose:** 用少量高品質真實案例作為 OW3gs 解牌參考與語法回測，不建立大量個人占卜流水帳。

## 1. 定位

本文件不是「占卜結果資料庫」。  
案例的用途是提供 **interpretation reference / validation evidence**，協助理解 OW3gs 在真實問題中的語意運作。

治理原則：

- 案例重質不重量。
- 原始問題、牌序、方向與當時解析不得被事後結果回寫。
- 事後結果另列為 verification evidence。
- 尚未發生完畢的事情只能標記 pending / partial verification。
- 遺失的舊解析不得依事後結果重新偽造。
- 教材人工範例與真實問事案例必須分開。

正式結構化資料：`data/json/registries/LOC1_OW3GS_READING_REGISTRY.json`

## 2. 現行 OW3gs 讀法

OW3gs 使用 11 張不重複 Base66 正式符文。

### 第 1–6 張：事情成因的描述層

描述：

- 成因
- 背景
- 條件
- 來源
- 脈絡
- 事情如何走到目前狀態

### 第 7–11 張：對於事情的建議文字層

形成：

- 主要回應
- 判斷
- 建議文字
- 對問題真正需要處理之處的聚焦

11 張不可平均成一個「整體吉凶分數」。  
前段描述可以很順，但最後仍可能得到不成立的結果；反之亦然。

## 3. 高價值回測案例

### 3.1 修車狀況

**牌序：**  
玄半逆、心半正、火正、月逆、愛半逆、幻正、根逆、暗正、土逆、封半正、老半逆

**當時核心判讀：**  
問題並不只在「能不能修」，而可能涉及根本老化、基礎穩定性與是否值得繼續投入。

**實際結果：**  
最後放棄修理舊機車，直接購買新車。原先只是考慮有額外預算就換車，後來基於舊車即使修好仍可能持續出現問題的風險，決定一次汰換。換車後目前使用狀況良好。

**回測原理：**

> 占卜不一定只回答問題的字面形式，也可能描述「更高一層的解決結構」。

這一案不是單純「修得好／修不好」，而是「修理方案本身被替換」。

---

### 3.2 找房子的策略方向

**牌序：**  
憶半逆、彩半逆、魂正、緣半逆、空正、光半逆、夢半正、域半逆、枝半逆、命半逆、分逆

**實際結果：**  
最後在舊家附近找到新住處，仍落在熟悉生活圈附近。

**回測原理：**

- 策略型問題可以回應「如何縮小搜尋空間」，而不是預測唯一地址。
- `域`、範圍、生活條件與熟悉場域的語意，比「一定搬到哪裡」更適合作為解讀層級。

---

### 3.3 凱基理賠狀況

**牌序：**  
命半逆、枝正、語逆、根半正、福正、氣正、草正、心半正、鍊正、金半逆、禍半逆

**實際結果：**  
理賠金額比原先預計少，而且處理速度非常慢；但因延遲，另支付一千多元利息。

**回測原理：**

> 多卡結果可以同時成立多個方向，不應壓成單一「好／壞」。

同一事件裡可以同時存在：

- 有給付
- 金額縮水
- 流程拖延
- 額外補償

因此 OW3gs 更適合作為複合事件描述，而非二元吉凶判定。

---

### 3.4 搬家的狀況

**牌序：**  
老逆、界逆、悟半逆、死正、花半逆、心逆、福正、草正、鑽半逆、金逆、暗半逆

**實際結果：**  
搬家整體圓滿完成，但成本很高。

**回測原理：**

- 「主結果」與「代價／成本」必須分開。
- 負向牌不必自動推翻整體成功。
- 回測時應避免抓住局部損耗，就把整個事件改寫成失敗。

## 5. 從目前案例可抽出的穩定原理

目前只先保留能被案例清楚支持的原理：

1. **描述層與回應層不可混成平均吉凶。**
2. **過程順利與結果成立是兩件事。**
3. **占卜可能描述問題的結構性解法，而非只回答問題字面。**
4. **多個結果可以同時成立：成果、延遲、成本、補償並不互斥。**
5. **主結果與代價必須分開判讀。**
6. **可能性、萌芽、互動不等於成熟結果。**
7. **長時間跨度問題必須等時間窗口完成後再做最終回測。**
8. **事後驗證的用途是修正語法理解，不是證明占卜「必然準確」。**
