# LOC Canon 1.1｜Search / Display Governance

正式補充治理文件｜2026-09-16  
作者：Lucas Oscar Wang 政德

> 本文件是 `docs/LOC_Canon_1.1.md` 的 Search / Display 領域補充治理。其目的為固定本次已定案的展示、作品關聯與作者文化搜尋原則，避免後續重複詢問或由 UI / Search 實作反向猜測規則。若未來主 Canon 整併本文件，應以整併後的 Current Canon 為準。

## 1. LOC 中立與自我約束

LOC 的中立不等於無治理，也不等於完全被動的工具。

- LOC 不替使用者決定價值、選擇或現實行動的正誤。
- LOC 可以並且必須約束自己的權限、資料責任與推論邊界。
- 對外中立：不代替人的判斷。
- 對內治理：限制系統自己的判斷權與資料越界。

固定原則：

> **中立不等於無治理。LOC 不替使用者決定，但 LOC 可以約束自己的權限。**

> **LOC 的中立，是對外不代替人的判斷；LOC 的治理，是對內限制系統自己的判斷權。**

此 Self-Constraint Principle 為上位治理原則，Search、KM、OW3gs、符文延伸體系與未來模組均應繼承。

## 2. 作品資料正規化

作品衍生關係全部保留，但不得因衍生而重複保存上游內容本體。

### 2.1 歌詞、歌曲、多媒體三層

- `lyrics_id`：歌詞文字本體。相同歌詞只保存一份完整歌詞。
- `song_id`：實際歌曲／旋律生成版本。同詞不同曲時，每個版本各自保留。
- `media_id`：Reel、MV、影片、影像等多媒體實例。

基本關係：

`media_id → song_id → lyrics_id`

固定原則：

> **同詞不同曲：歌詞唯一、歌曲分版；同曲不同媒體：歌曲唯一、媒體分筆。衍生關係全部保留，但上游內容不得因衍生而重複儲存。**

同詞不同曲屬少數例外，不應因此把一般資料模型設計成重複歌詞。

### 2.2 LOC3 曲風 Meta Tag

歌曲的 Meta Tag 以歌曲既有／原生曲風 metadata 為準，不要求作者重新人工分類。

- 同詞不同曲的不同歌曲版本可以具有相同曲風 Meta Tag。
- 曲風 Meta Tag 不負責判定哪一個歌曲版本較具代表性。
- 系統可做格式 normalization，但不得因此擅自改寫作品原生曲風定義。

### 2.3 代表歌曲推薦

作品保存與展示推薦必須分離。

- 同詞不同曲的歌曲版本全部保留。
- 已有人工作品整理與 Reels links 時，以人工整理資料作直接 provenance，不回頭從 Threads 或正文猜測關聯。
- 現行資料中，不建立「同詞不同曲的兩個 Reel 版本互相比較」情境；Reel 對應的是已人工選定的歌曲版本。
- 有 Reel 的歌曲版本為最高展示優先。
- 無 Reel 時，才以播放總次數作 fallback 排序。
- 推薦狀態不是 Canon 作品本體，不得因推薦結果刪除其他歌曲版本。

現行推薦順序：

`Reel-selected variant > total plays > fallback`

## 3. LOC5 多媒體最小責任

現階段 LOC5 不需要先建立複雜的多媒體語意引擎；先完成既有人工資料的基本交互與作品關聯。

最小鏈：

`Lyrics → Song → Reel / MV / Media`

LOC5 第一階段責任：

- 保存媒體類型與作品連結。
- 使用已提供並人工整理的 Reels links 建立關聯。
- 能由歌曲／歌詞找到 Reel、MV 等代表媒體。
- 能由 Reel／Media 回到對應歌曲與歌詞。
- 不重新分析 Threads 來猜測已有人工整理的 media relation。

後續 visual mood、scene、影像語意、LOC SV 跨媒體向量等屬延伸能力，不是目前基本交互成立的必要條件。

## 4. Search Preview 與全文分離

聚合搜尋與作品清單的 Preview 應使用「作品簡介」，不得用正文或歌詞節錄代替簡介。

- 歌曲：歌名 + 作品簡介 + 曲風 Meta Tag + 代表作品連結。
- 小說／文學：作品名 + 作品簡介 + 作品入口。
- Reel／Media：作品名／歌曲名 + 簡短說明 + 媒體連結。
- 只有使用者搜尋特定文字、需要定位原文命中 Context 時，才顯示正文／歌詞相關節錄。

固定原則：

> **作品聚合搜尋以作品簡介作為 Preview；不得以正文或歌詞節錄代替簡介。只有文字命中搜尋需要定位原文時，才顯示相關節錄。**

## 5. Progressive Context｜漸進式脈絡展示

主要實體頁與聚合搜尋採由淺入深的共同展示順序：

1. **Current 定義**：先回答現在是什麼，只以 Current 為主展示。
2. **代表特徵／代表詞**：顯示最能辨識該實體的 Current 關鍵詞或文化定義詞。
3. **代表作品**：優先提供少量可直接觀看／閱讀的代表作品；Reels 為重要代表入口。
4. **深入分析連結**：提供脈絡分析、文化解析、時期沿革、治理或其他深入頁面。
5. **完整資料入口**：完整作品清單、歷史資料、KM 與跨體系關係延後至下一層載入／點入。

固定原則：

> **Current 定義 → 代表特徵 → 代表作品 → 深入分析連結 → 完整資料。**

歷史沿革必須保留，但不與 Current 主展示混排；要了解演變時，由「沿革／脈絡分析」入口進入。

大量作品不得直接佔滿聚合搜尋主結果。完整作品清單應以可點入的集合入口承接，避免結果過長、重複與錯亂。

## 6. 「政德」Author Culture 聚合搜尋

搜尋 `政德` 時，不將所有包含政德的 KM records、歌曲、文章與 Reels 平鋪輸出。`政德` 應作為作者／作者文化的聚合實體入口。

展示順序：

1. **作者簡介**：Lucas Oscar Wang 政德的簡短 Current 介紹。
2. **Current 代表時期**：只顯示目前代表時期；歷史時期改由沿革／文化分析連結進入。
3. **Current 代表文化／風格定義詞**：例如政德風及 Current 文化核心詞。歷史代表詞如微月光、人生月台等保留為可搜尋、可遞回的文化節點，但不得取代 Current 主狀態。
4. **代表作品**：先提供代表 Reels，再提供代表小說／文章／歌曲的作品簡介與連結。
5. **深入入口**：政德風、脈絡分析、文化解析、時期沿革等。
6. **完整作品集合**：Reels、音樂、小說／文學、政德風文字、多媒體等以可點入作品清單承接。

### 6.1 「政德／政德風」Current 摘要治理

搜尋 `政德`、`政德風` 或進入作者首頁時，Current 摘要不得把「希望」寫成固定結尾或必然目的。

現行定義：

- 政德風優先真實、細膩地描述情感與現實，再視情況提供一個當下可能做得到的小調整。
- 建議必須保留可不採用的自由；不得把作者的答案寫成使用者必須遵循的方向。
- 不以強烈、不切實際或可能造成壓力的希望口號取代現實。
- 可以承認沒有立即解法、沒有保證、甚至沒有適合的建議。
- 「微月光」是此態度的代表意象：不是唯一的光，也不聲稱方向一定正確；它只在需要時提供一點溫暖、平易近人、具體而現實的參考亮度。
- 作者提供的是分析、經驗與建議，不替別人決定最後的路。

固定摘要：

> **真實描述 · 細膩感受 · 有限建議 · 不過度承諾 · 選擇權留給自己。**

文化詞與時期節點允許遞回：

`政德 → 文化詞／代表時期 → 定義與關係 → 代表 Reel／作品 → 深入分析 → 完整相關作品`

因此使用者即使完全不知道政德是誰，也能先由簡介與少量代表作品理解；若要深入，再進入文化與脈絡分析，而不是一開始面對完整作品資料庫。

### 6.2 「人生月台」Current 文化定義

「人生月台」不是單純等待，也不是消極停滯，而是人生轉換階段的中繼站與邊界區。

- 每個人都有自己的個人領域；領域可能是私密的，也可能是專業的。
- 人生遭遇突如其來的困頓、迷惑、結束或轉變時，會進入一段過渡期。
- 人生月台允許「不知道」：不知道下一步、下一站或該搭哪班車，都可以暫時成立。
- 邊界是過去的自己與現在的自己交錯之處；轉換期的責任，是回看過去、辨認現在，而不是假裝自己已經知道未來。
- 「以古鑑今」用於整理經驗，不是拿過去鎖死未來。
- 下一班車象徵新的可能；不必急著上車，但要為離開舊狀態做好斷捨離。
- 固定態度：**凡利於我者必利於我**。其作用不是保證外界結果，而是在未知中維持對自身選擇與利益的治理。

Current 摘要：

> **人生月台是一個允許不知道的地方。先面對過去、整理現在、做好斷捨離，再往新的未來移動；下一班車遲早會到，但沒有人能替你決定該上哪一班。**

### 6.3 「自由的風／自由的月」Current 文化定義

「自由的風」與「自由的月」必須接續「人生月台」理解，不得泛化為抽象的自由主題。

- **人生月台**：轉換期的中繼站。允許不知道，整理過去與現在，等待適合自己的下一班車。
- **自由的風**：新班次已進站，準備上車並尋找位置的過程。它不是描寫「自由」本身，而是方向已打開、位置尚未確定的開放可能；可類比自由座，班次已選定，但坐哪裡仍未知。
- 「風」在此表示尚未定著的空氣感與任意可能，不是逃離規則，而是尚未收斂成單一路徑的狀態。
- 此階段與月之符文「無（Blank / all possibilities）」的語意可形成文化上的對照：並非沒有內容，而是可能性尚未被固定。
- **自由的月**：承載這段移動的車子本身。班次已經啟程，人不再只是等待或找位子，而是在移動之中處理選擇、位置、邊界、取捨與航向。
- 因此「自由的月」的重點不是歌頌自由，而是**已經進入往未來移動的載體中，開始治理這段旅程**。

Current 關係：

> **人生月台＝轉換中繼站 → 自由的風＝班次進站後的上車／找位子 → 自由的月＝承載啟程、真正往未來移動的車子。**

### 6.4 創作脈絡、播放清單與 ERA 的分層

作者文化中的「創作脈絡」、「播放清單」與正式 ERA 必須分層處理。

- **ERA**：負責正式日期邊界、Current 狀態與歷史時期命名。
- **創作脈絡**：描述作品能力、情緒、主題與治理方法如何演化，可跨 ERA。
- **播放清單**：作品集合與觀看入口，可承載某一主題、系列或創作階段，但不得反向改寫 ERA 日期或時期邊界。
- 同一文化概念可以跨多個播放清單與 ERA；同一播放清單也可包含跨時期作品。
- Search / Culture 頁可同時顯示三者，但必須標明其層級，不把 playlist 名稱當成正式 period。

現行創作脈絡：

> **Suno 摸索 → 節奏王者 → 微月光／暗影篇章 → 浪潮系列 → 單身也很好／情緒權威 → 白晝之月 → 人生月台 → 自由的風 → 自由的月／治理自己**

其語意主線：

> **不知道 → 學習 → 找到節奏 → 描寫情感 → 校對現實 → 接受轉換 → 保留可能 → 治理自己。**

LOC 在作者文化中的一個重要比喻，是把走過的月台、路線、轉乘與時刻整理成可查詢的「時刻表」；這是分析與參考工具，不是替使用者決定必須搭乘的班次。

## 7. 時期展示治理

「時期」在聚合頁的責任是呈現 **Current 代表時期**，不是把全部 ERA 沿革直接展開。

- 主展示以 Current 為準。
- 過往時期完整保留。
- 歷史演變由沿革／脈絡分析／文化解析頁負責。
- 過往時期名稱仍可作 Search keyword 與文化節點，並連回其代表作品與分析。

如此可同時維持 Current clarity 與歷史可追溯性。

## 8. 月之符文首頁的代表 Reel

月之符文已有 Reel，因此月之符文首頁必須提供代表 Reel 入口，不應只有文字定義、抽牌功能或文件入口。

月之符文首頁同樣遵循 Progressive Context：

`Current 月之符文定義 → 代表特徵 → 代表 Reel → 脈絡／文化／治理／教學入口 → 完整符文資料`

代表 Reel 的作用是提供第一次接觸者低門檻的實際入口；深入資料仍由後續層級承接。

## 9. 資料來源優先序

若已有作者人工整理的結構化資料，系統不得為了重新推測而降低其 authority。

現行原則：

- 人工整理的 Reels links／作品關聯：直接作 media relation 來源。
- Threads 文本：屬 KM 文字與文化脈絡資料；不拿來重新猜測已人工確定的 Reel-song relation。
- 作品本體、簡介、Meta Tag、媒體關聯各自保存其 provenance，不互相覆寫。

此原則避免系統把已確定的人工資料重新變成不確定推論。

## Canon 摘要

本文件固定以下 Search / Display 治理：

- 中立不等於無治理；LOC 具有自我約束。
- 歌詞、歌曲版本、多媒體實例分層，避免內容重複。
- LOC3 曲風沿用原生 Meta Tag。
- Reel 是現行歌曲代表版本的最高展示訊號；無 Reel 才看播放總次數。
- 已人工整理的 Reels links 直接使用，不從 Threads 回推既有關聯。
- LOC5 先完成 Lyrics ↔ Song ↔ Media 基本交互，不過度擴張。
- 聚合搜尋顯示作品簡介，不用正文／歌詞節錄代替。
- Search／主要實體頁採 Progressive Context：Current → 代表特徵 → 代表作品 → 深入分析 → 完整資料。
- `政德` 搜尋是 Author Culture 聚合入口；Current 代表時期優先，沿革另行連結。
- 月之符文首頁必須提供代表 Reel 入口。
