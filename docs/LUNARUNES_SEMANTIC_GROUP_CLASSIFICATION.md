# LunaRunes Semantic Group Classification

## 定位

LunaRunes（月之符文）是 LOC 的 Symbolic Language Module。符文分類不是「看到某個中文字就判定某張符文」，而是先理解文本的語意，再依 LunaRunes 的 Canon、Spec、群組主體性與排他規則進行治理式分類。

本規格的第一個目標不是直接預測單一符文，而是先回答：

> 這一段文字的主要語意，最適合歸入 LunaRunes 的哪一個群組？

這個群組分類可作為後續符文候選、Search、RAG、Graph、作品統計與 Evolution 的共同前置模組。

## 核心原則

### 1. No API / No API Key

分類過程不呼叫任何外部 API，也不要求 API key。

第一階段由 Skill 直接依已提供的 LunaRunes 語意規格進行分析；不把文本送往第三方 embedding、LLM 或其他雲端分類服務。

這個設計的重點不只是成本，而是：

- 資料不必為了分類而送往外部服務。
- 判斷規則可讀、可檢查、可校準。
- 同一版本規格可以重新執行並比較結果。
- 後續可把穩定規則抽成獨立本地模組，供其他 LOC 功能共用。

### 2. 語意優先，不做單字命中

符文名稱、關鍵詞與反向關鍵詞都是 evidence，不是 trigger。

禁止以「文本出現某個符文字」直接判定群組；也禁止把簡單字串次數當作語意分類結果。

分類必須先判斷：

1. 這段文字的主體是什麼。
2. 它主要描述什麼關係、狀態、事件或概念。
3. 哪一組的核心語意最能承接這個主體。
4. 哪些看似接近的群組應被排除，以及原因。

### 3. 詞性與群組主體性先於表面詞彙

分類時先確認語彙在句中的作用，再判斷群組主體性。

固定順序為：**詞彙本身的詞性／句內語意角色 → 群組主體性 → 符文語意歸屬**。不得先以群組或符文猜測結果，再回頭替結果尋找詞性證據。

同一個詞在不同句子裡可能只是比喻、修飾、名稱或真正的語意主體。只有與群組核心語意一致時才能形成有效證據。

### 4. 每個語意單位只有一個唯一群組值

每個語意單位的正式 `group` 只能有一個值：

- 靈魂
- 連結
- 生命
- 自然
- 礦物
- 元素
- 秩序
- 無序
- 特殊

可以保留多個候選與權重，但正式分類不能同時輸出兩個群組。

### 5. 特殊組是預設值

`特殊` 是安全預設值，不是錯誤，也不是垃圾桶。

如果一般八組沒有足夠語意證據取得分類，或群組間仍存在無法合理消歧的衝突，正式結果可以維持 `特殊`。

一般群組必須靠證據取得，不為了提高覆蓋率而強迫分類。

### 6. 使用分配權重，但不把權重當成多重分類

分析時可對九類建立相對權重，以保存邊界資訊；權重用於比較，不改變「唯一 group」原則。

例如：

```json
{
  "group": "連結",
  "distribution": {
    "靈魂": 0.12,
    "連結": 0.42,
    "生命": 0.04,
    "自然": 0.03,
    "礦物": 0.02,
    "元素": 0.05,
    "秩序": 0.25,
    "無序": 0.03,
    "特殊": 0.04
  }
}
```

`distribution` 是判讀軌跡，不是九個同時成立的標籤。

### 7. 接近權重必須列入爭議

若第一名與第二名權重接近，必須：

- 仍輸出一個目前最合理的 `group`；若證據不足可維持 `特殊`。
- 設定 `disputed: true`。
- 保留主要候選群組與分數。
- 說明衝突點與目前選擇理由。

爭議資料不得被丟棄。它是之後調整 Spec、群組主體性、排他規則與 threshold 的治理樣本。

### 8. threshold 是可校準參數，不先寫死為 Canon

第一版 Skill 可以使用保守判斷，但不得把某個數值門檻宣告成永久 Canon。

應先累積真實文本，再依爭議案例調整：

- 第一名與第二名的差距門檻。
- 特殊組保留條件。
- 群組排他規則。
- 容易混淆群組的 disambiguation。

### 9. Canon 與現行語義優先

分類不得以歷史舊名或舊定義覆蓋現行 Base66／Canon。

既有重要治理例：

- 水 = Water；不可因為「流動」就判為水，流動的核心語意歸氣。
- 氣 = Air。
- 暗 = Shadow。
- 空 = Space。
- 無 = Blank / all possibilities。
- 虛 = Void。
- 玄 = Chaos；不可回退為 Mystery，也不可把所有一般性的混亂／失序都自動判為玄。
- 誤 = Error。
- 辰重在時期；時重在時間；緣可承接時機／契機，三者不可混成一般「時間」語義。

### 10. 可解釋與可重跑

每次分類至少保留：

- `group`
- `distribution`
- `disputed`
- `candidates`
- `reason`
- `evidence`
- `exclusions`
- `ruleset_version`
- `api_used: false`

這些欄位讓未來更新規格後可以重跑同一份文本，並比較分類變化。

## 分析層次

建議流程：

```text
原始文本
  ↓
語意單位切分
  ↓
句內詞性／語意角色
  ↓
群組主體性判斷
  ↓
九類相對分配
  ↓
排他與消歧規則
  ↓
唯一 group
  ↓
爭議標記
  ↓
後續符文候選／Search／RAG／Graph／Evolution
```

## 群組原則

群組名稱本身不是關鍵字。以下只作為第一階段的主體性提示；實際判斷仍須回到該組符文的現行 Canon 定義。

- **靈魂**：自我內部、精神、記憶、界線、領域、映照、核心等內在主體。
- **連結**：方向、建立／維持／中止／拆分關係、啟動、理解與錯誤等關係與連結變化。
- **生命**：生命歷程、身心狀態、情感、愛、語言與韻律等活體經驗。
- **自然**：生長、植物結構、根種花葉枝實等自然生命形態與生長關係。
- **礦物**：物質、地質、晶礦、硬度、壓力、稀有性、固態結構與材料特性。
- **元素**：光、影、水、火、風、土、雷、氣等元素性質與作用；必須遵守各元素的排他語義。
- **秩序**：日月星辰、清晰、時間、空間、因等可定位、可排列、可觀察的結構。
- **無序**：福禍、無、夢、幻、緣、虛、果等不確定、潛意識、空缺、結果與非線性關聯。
- **特殊**：分類安全預設；亦承接玄／命等特殊層。只有具體證據才能進一步說明是否接近玄或命，不能把特殊自動等同玄或命。

## 與符文層的關係

群組分類與符文分類分兩層：

```text
群組分類 = 第一層，唯一值
符文候選 = 第二層，可有多個候選與排序
```

先縮小群組範圍，再進行符文層判讀，可以減少 66 符直接全域比較造成的混淆，也讓 Search／RAG 的前置分類更快速、更模組化。

## 試驗階段

第一版以 Skill 方式驗證，不直接綁定 production Search/RAG runtime。

先用真實歌詞、小說、生活文字、FAQ／KM 等不同 corpus 觀察：

- 一般八組的可分性。
- 特殊組比例是否合理。
- 爭議案例集中在哪些群組邊界。
- 哪些 Canon／Spec 還需要補充 disambiguation。

待規則穩定後，再抽成共用 classifier module。
