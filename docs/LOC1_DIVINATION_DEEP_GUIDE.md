# LOC1 月之符文深入操作說明

**Status:** Current / Working  
**Updated:** 2026-09-07

## 1. 這份文件處理什麼

本文件處理「抽完之後怎麼讀」，不是符文本體字典。  
符文本體、月相、方向的母資料仍以正式資料庫與《命運句語法圖鑑》為準。

## 2. 不同張數的責任

- **1 張**：一個問題的一個語意焦點。
- **2 張**：兩個符文之間的關係。
- **3 張**：源－轉－合的基本結構。
- **5 張**：多面向情境；現行語法仍需持續驗證，不應把舊 2+3 拼接當最終規則。
- **11 張 OW3gs**：1–6 事情成因的描述層＋7–11 對於事情的建議文字層。

抽更多牌不是「比較準」，而是承擔更多語意責任。

## 3. OW3gs 解牌順序

### Step 1：先讀問題

先確認問題是在問：

- 狀況
- 策略
- 結果
- 關係
- 時間跨度
- 某事件的可行性

問題類型會影響「結果」應該被理解成什麼。

### Step 2：讀第 1–6 張

不要逐張各說一句後就結束。  
先找：

- 重複主題
- 現實條件
- 阻力
- 資源
- 未知因素
- 事情如何形成

這一段回答的是：

> 為什麼事情現在會是這樣？

### Step 3：讀第 7–11 張

這五張形成主要回應與建議文字。  
不要把前六張的情緒直接覆蓋這一區。

這一段回答的是：

> 面對這個問題，真正需要怎麼理解／處理？

### Step 4：再把兩層接起來

最後形成：

**成因描述 → 核心問題 → 回應／判斷**

而不是：

**11 張各自一句 → 算平均吉凶**

## 4. 真實案例教會我們的四個重要規則

### 4.1 過程 ≠ 結果

面試案例中：

- 面試官態度很好
- 成績漂亮
- 最後仍沒有錄取

所以「現場表現良好」不能被改寫成「一定會錄取」。

### 4.2 字面問題 ≠ 最終解決結構

修車案例最後不是「把舊車修好」，而是「放棄修理、直接換車」。

因此問題問 A，不代表牌只能在 A 的框架內回答。

### 4.3 多種結果可以並存

理賠案例同時出現：

- 金額比預期少
- 非常慢
- 有實際給付
- 另有延遲利息

不能因其中一項正向，就說整件事好；也不能因其中一項負向，就說整件事壞。

### 4.4 主結果與成本分開

搬家案例整體圓滿，但成本很高。

判讀時至少要分：

- 是否完成
- 完成品質
- 時間成本
- 金錢成本
- 情緒／體力成本

## 5. 事後回測

事後驗證不是「找牌來對答案」。

固定分四欄：

1. **原始問題**
2. **原始牌序與原解析**
3. **真正發生的事情**
4. **哪些語法規則需要保留、修改或否決**

### 禁止事項

- 不可看到結果後改寫原解析。
- 不可把模糊句子全部視為命中。
- 不可只紀錄成功案例。
- 不可把尚未走完的年度／月份問題提前判定。
- 不可用後來知道的資訊偽造當時就已經知道的含義。

## 7. 對《命運句語法圖鑑》的回寫原則

只有當同一規則：

- 能在一個以上案例中成立，或
- 在一個非常清楚的反例／驗證案例中顯示結構必要性，

才值得從 Reference Case 升格為語法說明。

案例是 evidence；語法才是 reusable knowledge。
