## 1. 這次的首要問題

**實際使用者回報：在「新增痕跡圖」選好數個錨點／站點後，按「儲存」，路線沒有成功成為可保存、可選取、可展示的結果。**

檢查原始碼可確認：
- `MapEditor` 的表單有 `onSubmit`，會呼叫 `save()`。
- `save()` 呼叫 `addTraceMap()` 或 `updateTraceMap()`；後者經 `dbAuthRelation(...).insert/update(...).select('uid')` 存取表格。
- 程式有 `await reload()` 和顯示「已儲存」訊息的分支。
- **但是使用者的實際儲存流程失敗；沒有瀏覽器 Network／回應與重讀對照，尚不能確定是 UI 事件、欄位驗證、授權／寫入回應、資料重讀、Scope 對應或展示階段哪個失效。**

**結論：現有「寫入程式碼」≠「基本功能正常」。先解決新增痕跡圖不能用的阻塞，其他功能不得宣稱已交付。**

### 資料語意

- **空間定錨點（anchor）**：有名稱、說明、經緯度及 `radius_m`；半徑是空間涵蓋範圍，不能視為同一地址的證明。
- **痕跡圖（map）**：有自己的名稱、說明，`anchor_uids` **有序陣列**代表站點先後。不同路線可以引用相同錨點；允許多張，不能強制只有一張。
- **文章地點（Galaxy `source_place`）**：文章原有打卡文字，可空白；不是文章分類，也不代表一定有經緯度。
- **時期（Period）**：篩選文章日期；**不能把一個地點有座標推定成某天曾造訪**。
- **站點直線連接**：是使用者編排的路線順序，不是經道路網驗證的真實移動軌跡。
