# Rune Narrative Occurrence Registry

## 定位

`RUNE_NARRATIVE_OCCURRENCE_REGISTRY.json` 記錄「符文在作品正文／章節裡實際出現、被使用或被提及的位置」。

這和下面兩種資料完全不同：

1. **Canonical rune definition**：符文本身的定義。
2. **Chapter generation three-rune record**：章節寫作前抽出的三張生成條件。
3. **Narrative occurrence**：成品正文中真正出現的符文。 ← 本 Registry

## 為什麼需要獨立

同一章可能：

- 生成時抽到 A / B / C 三符文；
- 正文最後實際出現 D / E / F 等更多符文；
- 某符文也可能只是世界觀、技能、物件、法陣或對話中的元素。

因此「抽牌」和「正文出現」不能互相替代。

## 治理規則

- 只記錄來源明確列出的正文出現符文。
- 不把正文出現推定為抽牌結果。
- 歷史名稱照原文保存，例如「意」「線」「蝕」不得自行改寫成現行符文。
- 未列出的章節只表示來源未記錄，不代表該章沒有符文。
- 後續可增加出現型態：提及、施放、物件化、世界觀、組合、敘事核心等，但必須有正文證據。
