# LOC 導覽治理原則

本文件定義 LOC 公開頁面的統一導覽命名與頁面首頁規則。後續新增或修改個人頁、治理頁及其他獨立功能頁，應以本原則為基準，不另創同義的功能名稱。

## 一、核心命名

第一個主要功能固定命名為 **語彙**。

「月之符文」是語彙層的具體內容／Symbolic Language Module，不另在主要 NAV 中建立「月之符文」、「符文圖鑑」等同層級的替代功能名稱。

主要功能順序固定為：

**語彙｜脈絡｜統計｜文化｜治理｜搜尋框｜作者介紹**

搜尋框是導覽中的固定搜尋元件，不以另一個功能頁名稱取代。

## 二、個人網頁 NAV

個人網頁使用：

**語彙｜脈絡｜統計｜文化｜治理｜搜尋框｜作者介紹｜回月典首頁**

## 三、月之符文 NAV

月之符文屬於「語彙」內容，其頁面仍可提供自己的功能入口，但不得重新定義主要功能名稱。

使用：

**語彙｜脈絡｜統計｜文化｜治理｜搜尋框｜作者介紹｜回月之符文首頁｜回月典首頁**

其中「回月之符文首頁」只表示當前語彙模組的本地首頁，不是新的主要功能名稱。

## 四、治理網頁 NAV

治理網頁使用：

**語彙｜脈絡｜統計｜文化｜治理｜搜尋框｜作者介紹｜回治理首頁｜回月典首頁**

其中「回治理首頁」只表示當前治理模組的本地首頁，不是新的主要功能名稱。

## 五、統一化原則

1. **主要 NAV 命名先於頁面內容命名。** 頁面內可使用月之符文、符文圖鑑、抽牌等具體名稱，但不得把這些名稱升格為主要 NAV 的同層功能。
2. **獨立功能保持獨立。** 抽牌、圖鑑、紀錄等若有獨立 route，使用頁面內功能入口或子路由處理，不藉由新增同義 NAV 名稱破壞統一架構。
3. **本地首頁採返回連結表示。** 個人頁、月之符文頁、治理頁各自可有「回本頁首頁」，並保留「回月典首頁」作為上層返回。
4. **不因單一模組而改寫全站主導航詞彙。** 模組可擴充內容，但主要 NAV 使用固定 Canon。
5. **個人風格頁比照本原則。** 個人風格頁（如作者個人風格、政德風）沿用相同主要 NAV，不另外發明一套導覽術語；其差異只出現在本地首頁返回項目或頁面自身內容。

## 六、治理目的

導覽文字屬於資訊架構（Information Architecture）的一部分，應視為系統治理內容。避免同一功能在不同頁面被重新命名，降低認知負擔、避免語意污染，並讓 LOC 的模組化結構在 UI 層保持一致。
